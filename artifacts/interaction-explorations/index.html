Resume Studio interaction explorations

How should the document behave while it is being written?

These explorations focus on workflow, navigation, contextual editing, and long-session behavior. They are intentionally text-heavy so the interaction model is easier to study than any one visual style.

What we are testing

  • Whether editing should happen inline, in a dock, or through a manuscript-style annotation flow.
  • How navigation can become structural instead of tab- or pill-based.
  • How guidance can feel ambient, editorial, and present without occupying a permanent panel.

Direction 01

Inline Editing + Contextual Dock

Editing philosophy

The resume is edited where it lives. The dock appears only beside the active section or paragraph, so the page still feels like the app.

Navigation and guidance

Navigation is structural and section-based. Guidance arrives as calm nudges in the dock and faint inline annotations on the page.

Open exploration

Direction 02

Manuscript / Annotation Workflow

Editing philosophy

The interface behaves like a draft manuscript with margins, notes, and revisions. Controls become annotations, not panels.

Navigation and guidance

The user moves through highlighted passages and note markers. Guidance reads like editorial commentary tied to specific sections.

Open exploration

Direction 03

Structural Document Map + Focus Follow

Editing philosophy

The document map is the lightweight spine of the app. It tracks structure, current focus, and page position without becoming a permanent sidebar.

Navigation and guidance

Keyboard and scroll behavior drive focus. The map follows the current section while a docked inspector appears only when a section needs attention.

Open exploration

Each page is static HTML/CSS only and is meant to help us decide how Resume Studio should fundamentally behave, not how it should be styled.
